# viva-marketplace

The **ecosystem ledger** for the [vivarium](https://github.com/vivarium-collective) /
[process-bigraph](https://github.com/vivarium-collective/process-bigraph) workbench.

It answers three questions for the [vivarium-workbench](https://github.com/vivarium-collective/vivarium-workbench)
Registry, so a workbench can browse the **whole ecosystem** — not just what's
installed locally — and offer **Install to use**:

| File | What it is |
|---|---|
| [`viva_marketplace/modules.json`](viva_marketplace/modules.json) | The registry of ecosystem repos — `name`, `source`, `description`, `tags`. The single source of truth for *what repos exist*. Validated against [`schemas/modules.schema.json`](viva_marketplace/schemas/modules.schema.json). |
| [`viva_marketplace/ecosystem-index.json`](viva_marketplace/ecosystem-index.json) | The aggregated **artifact index** — every repo's processes / steps / composites / studies / investigations (name + description + counts), plus a per-repo **reproducibility attestation** score. Regenerated by CI. Validated against [`schemas/ecosystem-index.schema.json`](viva_marketplace/schemas/ecosystem-index.schema.json). |
| [`viva_marketplace/composability-graph.json`](viva_marketplace/composability-graph.json) | **Experimental** — a best-effort, statically-extracted cross-repo port compatibility graph: which processes from *independently authored* repos might wire together. See [Composability graph](#composability-graph-experimental) below. |

Previously the registry lived in `viva_superpowers/catalog/modules.json` (the
Claude-Code plugin). It moved here so the ledger is owned by a dedicated repo.

**Adding or updating a repo?** See [CONTRIBUTING.md](CONTRIBUTING.md) — you open a
PR editing `modules.json`; the artifact index rebuilds itself from your repo's
source.

## How the index is built

`scripts/build_ecosystem_index.py` reads `modules.json` and, for each repo,
**shallow-clones it and scans the source** — no published dashboard required.
The extraction logic itself lives in `viva_marketplace/scanner.py` (shared
with `viva_marketplace.selfcheck` — see below), and covers:

- **composites** — `@composite_generator(name=…, description=…)` decorators (AST)
  + any `*.composite.yaml` files
- **processes / steps** — top-level classes whose base ends in `Process` / `Step`
  (AST), described by a `description` class attribute or the class docstring,
  plus a best-effort `ports` dict when `inputs()`/`outputs()` resolve to a
  literal `return {...}` (see [Composability graph](#composability-graph-experimental))
- **studies** — `**/studies/*/study.yaml` (name + objective/title)
- **investigations** — `**/investigations/*/investigation.yaml` (name + title)
- **attestation** — see [Reproducibility attestation](#reproducibility-attestation) below

This gives complete coverage across the ecosystem whether or not a repo publishes
a workbench dashboard. Repos that can't be cloned are still listed (empty
artifacts, `cloned: false`).

```bash
python scripts/build_ecosystem_index.py                              # rebuild everything
python scripts/build_ecosystem_index.py --only Viva-munk,pbg-copasi  # subset (debug)
python scripts/build_ecosystem_index.py --jobs 16                    # more parallel clone+scan workers
```

Needs `git` + `pyyaml` + `jsonschema` (`pip install -e ".[dev]"` for local development).

## Reproducibility attestation

Most bio-software registries score FAIR-ness via manually-filled
questionnaires. Since this builder already clones and scans every repo, it
computes a real attestation **for free** during that same pass — no
simulation execution, no manual form:

- **pinned_ref** (weight 0.25) — the registry `ref` is a full 40-hex commit
  SHA, not a floating branch/tag. A floating ref means "what gets built"
  silently changes over time.
- **has_lockfile** (0.15) / **has_license** (0.15) / **has_citation** (0.10)
- **schema_version_present** (0.10) — a `workspace.yaml` declares its schema
  version, so tooling changes don't silently reinterpret it.
- **acceptance_criteria / baseline coverage** across `studies/*/study.yaml`
  (0.15 / 0.10) — excluded from the weighted average entirely (not scored 0)
  when a repo has zero studies, so process-library repos aren't penalized for
  a study convention that doesn't apply to them.

The result (`repo.attestation.score`, 0–1) is a **heuristic signal, not a
certification** — presence of these artifacts correlates with reproducibility,
it doesn't guarantee it. See `viva_marketplace/scanner.attest()` for the exact
implementation.

## Composability graph (experimental)

Process-bigraph Processes/Steps declare typed `inputs()`/`outputs()` ports.
When a port dict is a literal (`return {"flux": "float"}`) — not computed from
`self.config` — the scanner records it. `viva_marketplace/composability.py`
then matches producer output types to consumer input types **by exact string
equality, across independently-authored repos**, and writes the result to
`composability-graph.json`.

This is a genuinely new capability for this ecosystem: a way to discover
composition opportunities across process libraries nobody has fully
inventoried by hand. It is **not** a verified wiring guarantee — matching
ignores unit/shape semantics, and coverage is inherently partial (most real
ports are computed dynamically and are simply invisible to a static scan).
Always confirm by actually composing.

## `selfcheck` — drift check before you open a registry PR

```bash
viva-marketplace-selfcheck <your-registry-name> --path .
# or: python -m viva_marketplace.selfcheck <your-registry-name> --path .
```

Reuses the exact same `scanner` logic as the nightly build, pointed at your
local checkout instead of a fresh clone, so it can never drift from "what the
ledger will actually see." Reports:

- whether your local artifact counts match the last published
  `ecosystem-index.json` (or flags that the index is stale/not yet built)
- whether your `modules.json` entry is missing a `description`/`tags`
- (forward-looking, opt-in) if your package exposes
  `<package>.marketplace_info.get_info()`, folds that self-declared metadata
  into the comparison — mirrors pbg-ptools' `workbench_viewers.get_viewers`
  duck-typed discovery. No package needs to implement this today.

Entirely informational — it never writes to `modules.json` and never fails a
build; the registry stays hand-edited and PR-reviewed.

## Consuming the ledger

**Python** (viva-superpowers, vivarium-workbench):

```python
import viva_marketplace
repos = viva_marketplace.load_modules()               # the repo registry
index = viva_marketplace.load_ecosystem_index()        # aggregated artifacts + attestation
graph = viva_marketplace.load_composability_graph()     # EXPERIMENTAL port-compatibility graph
schema = viva_marketplace.load_schema("ecosystem-index.schema.json")
```

**Over HTTP** (published to gh-pages, same-origin for any published workbench):

```
https://vivarium-collective.github.io/viva-marketplace/modules.json
https://vivarium-collective.github.io/viva-marketplace/ecosystem-index.json
https://vivarium-collective.github.io/viva-marketplace/composability-graph.json
```

## CI

- [`.github/workflows/validate.yml`](.github/workflows/validate.yml) — PR gate
  on any `modules.json`/schema change: `scripts/validate_modules.py`.
- [`.github/workflows/test.yml`](.github/workflows/test.yml) — pytest + ruff +
  mypy on any change to the package/scripts/tests.
- [`.github/workflows/build-index.yml`](.github/workflows/build-index.yml) —
  rebuilds `ecosystem-index.json` + `composability-graph.json` daily (and on
  relevant pushes to `main`), schema-validates the output, commits it, and
  publishes `modules.json` + both generated files to `gh-pages`.
- [`.github/workflows/verify-publish.yml`](.github/workflows/verify-publish.yml) —
  post-publish smoke test: fetches the **live** gh-pages JSON (not the local
  build output) and schema-validates it, catching publish-lag/staleness the
  build job's exit code can't see.
